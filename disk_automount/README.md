# Disk Automount (Volumio plugin)

Схема «Volumio на флешке/SD, музыка на отдельном внутреннем диске»: диск выбирается по UUID,
монтируется при загрузке и появляется в библиотеке MPD. Переустановка Volumio музыку не трогает.

## Как это устроено (почему нет костылей)

Плагин работает от обычного пользователя `volumio`. Всё, что требует root, делает **systemd**:

```
плагин (volumio) ──пишет──► /data/configuration/system_hardware/disk_automount/request
                                   │  (следит disk-automount.path)
                                   ▼
          disk-automount-apply.service ──root──► /usr/local/sbin/disk-automount
                                   │
плагин ◄──читает── /run/disk_automount/status ◄──┘
```

* Никакого `sudo`, никаких правок `/etc/sudoers`, `/etc/fstab`, `index.html` Volumio.
* `install.sh` только **добавляет** новые файлы с уникальными именами (помощник + 3 юнита).
* Помощник читает заявку как данные (не `source`, не `eval`), каждое поле проверяется по строгому шаблону.
* Помощник сам отказывается трогать системные диски (`mmcblk`, метки `volumio*`, `boot`, `imgpart`,
  всё, что смонтировано в `/`, `/boot`, `/data`, `/imgpart`, `/static`), имена `INTERNAL/USB/NAS/UPNP`,
  диск, уже смонтированный где-то ещё, непустую папку.
* Любая проверка выполняется **до** изменений: при ошибке текущее состояние остаётся как было.
* Размонтирование без `-l`/`-f`: если диск занят, получите понятную ошибку, а не повреждённую ФС.
* Прав `777` нет. FAT/NTFS/exFAT: владелец `volumio`, остальным чтение; переключатель
  «Запись для всех» включает `umask=000`. Ext4/xfs/btrfs: сохраняются собственные права, у корня диска
  владелец меняется на `volumio`, если он был `root`.

## Требования

- Volumio 4 (Debian 12 «Bookworm»), архитектуры `amd64` или `armhf`.
- Диск с файловой системой ext2/3/4, xfs, btrfs, ntfs, exfat или vfat.
- Node-зависимости `kew` и `v-conf` ставятся при `volumio plugin install`.

## Установка (по SSH на Volumio)

Сначала удалите старый плагин `hdd_automount` (его `uninstall.sh` уберёт правки sudoers/fstab).

```bash
git clone https://github.com/karkolom223/volumio_plugin.git
cd volumio_plugin/disk_automount
npm install --production      # kew, v-conf (при установке из zip это делает volumio)
volumio plugin install
```

Затем: «Плагины → Установленные плагины → Disk Automount → включить», выбрать диск, имя папки,
«Сохранить и смонтировать».

## Что проверено, а что нет

Проверено в песочнице (Linux, root, loop-устройство ext4): синтаксис, shellcheck без замечаний,
около 25 сценариев помощника (монтирование, повтор, переименование, конфликт ссылки, непустая папка, диск
смонтирован в другом месте, чужой mount, занятый диск, метка системного диска, boot/cleanup,
попытки инъекции в UUID и имя) и связка плагина с помощником через заглушки ядра Volumio.

**Не проверено** (нужен реальный Volumio): поведение пользовательских systemd-юнитов после обновления
системы, видимость симлинка в браузере файлов Volumio, работа `ntfs3`/`ntfs-3g` на вашем образе.
Проверьте после установки: `systemctl status disk-automount.path disk-automount.service`,
`journalctl -t disk_automount`.

## Известные особенности

* Если диск при загрузке отсутствует, старт ждёт его до 15 с, затем продолжается без ошибки.
* Сервис стоит перед `volumio.service`, поэтому диск монтируется до запуска MPD.
* Одна настройка диска. Для нескольких дисков нужна отдельная доработка.

## Сдача в volumio-plugins-sources

Структура и `package.json` соответствуют требованиям (`volumio_info`, `plugin_type`, `architectures`,
`os`, `changelog`, лицензия MIT). Решение принимает команда Volumio; помощник и юниты вынесены в
отдельные файлы, чтобы ревьюеру было что читать.
